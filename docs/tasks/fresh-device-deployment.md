# 新设备部署与统一维护整改

根任务11-15-fresh-device-lifecycle-deployment，已批准implementation-contract.md及每端六类功能入口各一次的有限真实验证。沿现有main实施，先测试、提交推送、正式发布、本地home部署验收，再部署PennixLaptop。目标已有0.3.8及基础环境；控制端0.3.10。

## 修改边界

凭据缺口由secret_store/credential_import与CLI承接，增加所选字段检查及私有中央来源传输，保留现有owner来源、权限与冲突保护；不增加秘密服务。Copilot增加现有AUR来源及首装pending处理，不关闭现役外部接入。relay按原生身份生成后的顺序登记，不复制或手写server-id。

统一更新拆出只读inventory与工具公开发行发现，CLI复用现有candidate、lock、journal和apply执行步骤，保留单组件接口及恢复。本轮预期涉及上述模块、pennix.py、connection_owners.py、catalog/Kconfig、必要测试和文档，不新增工作树、后台任务、通用包管理器或未审查的自动升级。

## 验证与接受

需要覆盖秘密值不入输出、字段/权限/冲突/超时、缺依赖首装、身份与远端登记、只读真实DB保留、候选与输入冻结、全系统升级后重规划、unknown恢复，以及旧接口兼容。完整隔离源码测试和实际正式载荷验证通过后发布；本地和目标真实验证及保留、资源、根组合验收由根任务记录。真实模型/搜索入口各端各最多一次，失败不扩大调用。

## 0.3.13 本机验收发现的版本解析修复

0.3.12 已通过源码 274 项、实际本地及公开载荷、CI 与公开摘要回读，安装到 home；目标尚未部署。Pandoc 原生 reconcile 拒绝旧回执与锁不一致，根因是通用版本解析器取了输出最后一个版本：Pandoc 3.11 的末尾依赖 Lua 5.4 被写入旧回执。改为首个程序版本；仅对已复现 Pandoc 路径允许受限旧回执恢复，要求可信同源 receipt、真实 pacman 可执行归属、旧锁/实际包/程序上游版本均相同，且旧回执精确等于旧解析结果。其他不一致仍阻断，不安装、降级或手写回执。通过确认的原生 reconcile 同步记录后再全局验收。
